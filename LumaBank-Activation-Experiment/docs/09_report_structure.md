# LumaBank Activation — Report Structure

**Document status:** Phase 8 deliverable. The Power BI report is the **secondary**
deliverable — the primary read-out is `data_analysis/`. 4 pages, code-generated. One
command rebuilds it:

```
cd powerbi && bash build_report.sh
```

Pipeline: `gen_logo.py` → `gen_semantic_model.py` (+ `pbi_measures.py`) →
`gen_dax_doc.py` → `gen_report_visuals.py` → `build_report.sh` (drives `pbir`).
Output: `powerbi/LumaBankActivation.pbip` + `.Report` + `.SemanticModel`.
`pbir validate --all` passes.

**First open in Power BI Desktop:** Transform data → set `pDataFolder` to
`data/curated` → Close & Apply · View ▸ Themes ▸ Browse → `powerbi/theme/theme.json`.

---

## Semantic model

18 imported curated tables + `_Measures` (46 measures in 9 folders, see
`docs/06_dax_measures.md`), 22 relationships. `fact_activation` (one row per signup,
platform-wide) drives Executive Overview and the funnel page; the Experiment Readout
group filters to `in_analysis_flag = TRUE()` — the clean re-run population only, so
the read-out never mixes the broken original run with the clean one.

---

## The four pages

No on-canvas slicers — each page has a fixed analysis window baked into its measures
(platform-wide vs. `in_analysis_flag`-filtered), matching the incident narrative rather
than letting a slicer blend broken and clean data. Page backgrounds carry the header
band + kicker + page title, generated by `gen_report_visuals.py` from `assets/brand.py`.

| # | Page | Question | KPI row (4 cards) | Content |
|---|---|---|---|---|
| 1 | **Executive Overview** | Is the platform healthy, and did the redesign work? | Signups · Active Rate % · Day-7 Activation Rate % · Exp Lift pp | Day-7 Activation by channel (column) · `Exec Insight` narrative card · Day-7 Activation trend (line) |
| 2 | **Onboarding & Activation Funnel** | Where do new users fall out on the way to activation? | Account-Creation Rate % · Day-7 Activation Rate % · KYC-Submit Rate % · Median Minutes Signup→Account | Onboarding funnel (funnel chart) · KYC rejection by channel (column) |
| 3 | **Experiment Integrity Monitor** | Can the experiment be trusted right now — allocation, SRM, contamination? | Allocation Ratio (Treatment Share) · Contaminated Users · SRM P-Value (Trailing 7d) · SRM Worst State | Allocation vs. SRM p-value (line) · fallback-share trend (line) · snapshot-log mismatch trend (line) — *this page exists to tell the break story visually* |
| 4 | **Experiment Readout** | Once the experiment is clean, what is the effect? | Exp Control Rate · Exp Treatment Rate · Exp Lift pp · Exp Significant 95% | Effect by channel (column) · guardrails (multi-row card: KYC-rejection and flagged-fraud non-inferiority) |

## Known lite-scope gaps (not polished)

  (`in_analysis_flag`), not by a user-facing control.
- No screenshot-verification loop (needs a live Desktop session).
- `Exec Insight` is a dynamic text measure (no Smart Narrative visual).
