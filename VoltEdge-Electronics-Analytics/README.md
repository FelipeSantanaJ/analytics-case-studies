# VoltEdge Electronics — Executive Analytics

End-to-end analytics portfolio project: a synthetic-but-realistic consumer-electronics
e-commerce, taken from **raw source-system exports** all the way to an **executive Power BI
report** and a **dual-track (SQL + Python) analysis**, with the full data-engineering
pipeline and documentation in between.

The project demonstrates four skill sets in one coherent piece of work:

| Skill area | What this project shows |
|---|---|
| **Data engineering** | A reproducible, seeded Python pipeline that generates messy multi-source raw data, cleans and conforms it (medallion architecture), enforces data-quality checks, and publishes a documented star schema in Parquet/CSV. |
| **Data modelling** | A Power BI semantic model built as code — 28 tables, ~65 relationships, a **167-measure DAX library** with multi-currency re-denomination, budget-vs-plan, comparable-base (like-for-like) and a dynamic narrative measure. |
| **Dashboard design** | A 7-page executive report — theme, layout and every visual — built and version-controlled through the `pbir` project format, with a committed visual identity. |
| **Data analysis** | A dual-track analysis (**DuckDB SQL + pandas**, every result parity-checked) that produces **10 findings** and two audience-specific deliverables: a board summary and an extensive deep dive. |

📄 [Visual case study (PDF)](portfolio/VoltEdge-Electronics-case-study.pdf) — 7-page carousel summary.

## The scenario

**VoltEdge Electronics** is a fictional pure-play online retailer of consumer electronics
(smartphones, laptops, audio, gaming, smart home, wearables, accessories). It sells
direct-to-consumer across four markets, launched in sequence:

| Market | Currency | Live since |
|---|---|---|
| United States | USD | 2022 (before the extract window) |
| United Kingdom | GBP | 2025-01 |
| Germany | EUR | 2025-01 |
| Brazil | BRL | 2025-07 |

The analytics extract covers **2024-07-01 → 2026-06-30** (24 months) so every metric has a
full **year-over-year** comparison. Because UK/DE/BR go live *inside* that window, growth is
always shown two ways: **Total** and **Comparable Base** (US like-for-like), with the
difference reported as **Expansion Contribution**.

Reporting currency is **USD**; transactions are captured in local currency (USD/GBP/EUR/BRL)
and converted at daily rates. The model also covers **payments** (fees by scheme,
instalments, settlement lag) and **working capital** (procurement, inventory ledger,
DIO/DSO/DPO and the cash conversion cycle).

> All data is synthetic and generated by the scripts in [`etl/`](etl/). No real company,
> customer or transaction is represented.

## The Power BI report — `powerbi/`

Generated as code and assembled with the `pbir` CLI (`cd powerbi && bash build_report.sh`).

- **Semantic model** (`*.SemanticModel/`, TMDL) — 28 tables (16 dims + 12 facts), each an
  import partition over the curated Parquet via a `pDataFolder` parameter; ~65 relationships
  (secondary date roles inactive, switched on with `USERELATIONSHIP`); disconnected helper
  tables for the currency selector, funnel and bridge visuals.
- **DAX** (`etl/pbi_measures.py` → `_Measures` table) — **167 measures** in 14 folders:
  Net Revenue / Gross Profit / Contribution Margin, time intelligence, comparable base,
  targets vs plan, reporting-currency re-denomination (USD / EUR / GBP / BRL from one
  slicer, with a dynamic currency symbol), payments & cash, price-volume-mix, marketing,
  website funnel, logistics, working capital, CRM, support & returns, plus a dynamic
  **Exec Insight** narrative measure.
- **7 pages, one business question each** — Executive Summary · Sales Performance ·
  Marketing & Acquisition · Website & Digital · Logistics & Fulfillment · CRM & Customer ·
  Product & Inventory. Each: a navy signature header, a Currency + Market slicer row, an
  Analysis-Period date slicer, a row of 6 KPI tiles, then two content rows on the 3-30-300
  gradient.
- **KPI tiles** — a value card plus a "vs Target" delta, coloured green / red on the same
  sentiment scale as the waterfall bridges (inverted for lower-is-better metrics), on a
  white rounded frame.
- The Executive Summary carries the Exec Insight paragraph, a monthly + trailing-12-month
  contribution-margin chart, a budget scorecard, and **four bridges** (net revenue and
  contribution margin, each by product category and by region).

## The data analysis — `data_analysis/`

Every result is computed **twice** — DuckDB SQL and pandas — and the two must agree
(`data_analysis/parity/NN_*.py`, all printing `ALL PARITY CHECKS PASSED`). See
[`data_analysis/00_START_HERE.md`](data_analysis/00_START_HERE.md) for the method and
[`data_analysis/README.md`](data_analysis/README.md) for how to run it.

Ten parity-verified findings (`data_analysis/findings/`):

| # | Finding | Headline |
|---|---|---|
| 00 | Anchor — Net Revenue | $31.35M over 24 months; reproduces the DAX exactly on both tracks |
| 02 | Growth is mostly expansion | +137% total vs **+40% US like-for-like**; US is −2% vs plan |
| 03 | Contribution margin | Reached break-even (+$0.3M CY vs −$0.4M PY); UK the only negative market |
| 04 | US growth is all volume | +110% volume, +8% price, −17% mix (into thin-margin smartphones) |
| 05 | Promo depth erases gross profit | Promo days ≈ −$0.3M/yr of gross profit vs a normal day [95% CI: −$0.38M, −$0.24M], p < 0.001 |
| 06 | Working capital is the real problem | CCC ≈ 134 days, all inventory; **~$4.4M cash freeable** |
| 07 | CM depends on cheap CAC | +$0.3M at $26.91 CAC, but **−$0.05M at the $32.80 plan CAC** |
| 08 | Retention healthy, not yet the engine | Repeat rate 37.6% (above benchmark) but decays fast |
| 09 | Returns margin leak | 8.0% rate (fine), but a **$1.65M net margin drag**, ~63% controllable |
| 10 | Fulfilment & shipping recovery | On benchmark; only lever is shipping-fee recovery (28%; BR 5%) ≈ $0.6M/yr |

Two deliverables in `data_analysis/deliverables/`:
- **`board_summary.{html,pdf}`** — short, decision-first, the findings that change a call.
- **`deep_dive.{html,pdf}`** — the exhaustive record: each business problem with context,
  method on both tracks, evidence, limitations and a recommendation.

## How to run

```bash
# 1. the data pipeline (raw → staging → curated → DQ gate)
cd etl
python -m pip install -r requirements.txt
python run_pipeline.py                      # deterministic — re-runs reproduce byte-identical data

# 2. the Power BI report  (close Power BI Desktop first)
cd ../powerbi
bash build_report.sh                        # pbir validate --all at the end

# 3. the analysis
cd ../data_analysis
pip install duckdb matplotlib seaborn pandas pyarrow
for f in parity/*.py; do python "$f"; done  # all must print ALL PARITY CHECKS PASSED
python deliverables/build_deliverables.py    # rebuild the two HTML deliverables
```
